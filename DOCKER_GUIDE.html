Start

Status and readiness

curl http://localhost:8000/health/ready

Restart

docker compose -f compose.production.yml restart api
docker compose -f compose.production.yml restart sync
docker compose -f compose.production.yml restart frontend

Stop safely

docker compose -f compose.production.yml down
Never add -v unless you intentionally want to delete all three database volumes.

5. Release an update

Use immutable versions such as 1.0.1. Production Compose should use the versioned tag, not only latest.

# Example backend update
docker build -f Dockerfile.publish \
  -t farzanehmajd/gs-backend:1.0.1 \
  -t farzanehmajd/gs-backend:latest .
docker push farzanehmajd/gs-backend:1.0.1
docker push farzanehmajd/gs-backend:latest

# Change compose.production.yml from :1.0.0 to :1.0.1, then:
docker compose -f compose.production.yml config -q
docker compose -f compose.production.yml pull
docker compose -f compose.production.yml up -d
Compose recreates changed services while preserving named database volumes.

6. Database and volume safety

List volumes

docker volume ls | grep -E "gs-production|postgres|influx"

PostgreSQL backup

cd "/d/APSCO/Full Ground Station/GS-backend/gs_backend"
docker compose -f compose.production.yml exec -T postgres \
  pg_dump -U gs -d groundstation > groundstation-postgres-backup.sql

PostgreSQL restore

docker compose -f compose.production.yml exec -T postgres \
  psql -U gs -d groundstation < groundstation-postgres-backup.sql

Schema revision

docker compose -f compose.production.yml exec api alembic current
The API automatically executes alembic upgrade head during startup. Do not manually edit an applied migration revision.

netstat -ano | grep -E ":(3000|8000|8086|8087|5433) "
API is unhealthy
docker compose -f compose.production.yml ps
docker compose -f compose.production.yml logs --tail=150 api
curl -i http://localhost:8000/health/ready
Registry says “versions: none”

This normally indicates blocked/intermittent registry access. Use the tested offline Dockerfile.publish workflows; do not downgrade valid pinned dependencies.

Clean unused build cache
docker builder prune

Review the confirmation carefully. Do not add --volumes.

8. Deploying to a remote server

The current frontend calls localhost:8000 and is intended for a browser on the same computer. For a remote host, set its real IP/domain in .env.local before building a new frontend version.

NEXT_PUBLIC_DATA_SOURCE=graphql
NEXT_PUBLIC_GRAPHQL_HTTP_URL=http://YOUR_SERVER_IP:8000/graphql
NEXT_PUBLIC_GRAPHQL_WS_URL=ws://YOUR_SERVER_IP:8000/graphql
Before internet exposure, add HTTPS/TLS, authentication, authorization, command approval controls, a reverse proxy and firewall rules. The current GraphQL service is for a trusted local network.

9. Rules worth remembering

  • Never publish .env, passwords, tokens or API keys.
  • Never run docker compose down -v accidentally.
  • Never run docker system prune -a --volumes without verified backups.
  • Use versioned tags for production deployments.
  • Keep COMMAND_SIMULATION=true until the real F Prime bridge and safety controls are validated.
  • Replace the development telemetry catalog with the authoritative F Prime dictionary before flight use.
  • Back up databases separately; Docker Hub only stores images.
